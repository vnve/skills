# 视觉小说的制作与演出

常用人物动作、镜头、氛围和转场先按 [常用视觉入口](common-effects.md) 选择；复杂构图与算法继续使用原子 SDK。

新作、长文本改编、节奏重做或批量制作时读取。以下方法是将 Ren’Py / Naninovel 的经验用于 **线性视频** 的制作建议；游戏里的点击继续不能代替视频中的阅读时间。本文件中的节拍表是创作笔记，不是运行时 JSON 或新增 CLI 命令。

## 先决定观众会看到和听到什么

从用户文本与已有作品提取观看画幅、时长、语言、氛围、是否配音及素材来源；仅询问会改变制作结果的缺口。需要选择时，展示两三种具体方案：例如“立绘对白为主 / 插画叙事为主”“先无声试片 / 用户录音 / 已选外部 TTS”，沿用用户已有授权。

把连续文本拆成叙事节拍（beat）：每段有明确的新信息、反应或情绪转折。按意义拆，不机械规定每句字数或每场台词数。旁白交代画面不能直接表达的信息，避免逐字描述已经能看到的动作。重要揭示前后允许静止、留白或反应；动画密度取决于叙事目的。

新作先在 script 草稿中声明本轮角色、地点与外观，再 create。续写通过结构 Patch 增加幕、场景、故事身份、演员和状态，媒体先 import 再绑定，保留原节点及录音；见 [原子编辑](editing.md)。小作品可只做当前范围，不为未来情节生成全套素材。

## 用节拍表推导执行内容

复杂或需要恢复的制作，可把 brief、节拍表与素材卡存为 workspace 下的 `production/` 笔记；小改动保留在对话即可。笔记不替代 Project，引用 ID 以 inspect 为准。记录有用信息：

| 节拍 | 文字与意图                   | 画面与连续性                               | 声音与时间依据                           |
| ---- | ---------------------------- | ------------------------------------------ | ---------------------------------------- |
| 到达 | “你终于来了。”；确认对方出现 | 两人建立空间关系；复用地点日常图           | 录音实际时长，或无声估时；保留读完的时间 |
| 犹豫 | 对方停顿后回答；表达退缩     | 朝向、微小位移或静止反应；保持人物左右关系 | 标出停顿位置；不是虚构音素对齐           |
| 决定 | “我们出发吧。”；关系推进     | 一次有目的的动作或镜头变化                 | 检查尾字、读后停留与场景交接             |

节拍不是固定动画预设。模型可创作任意受支持数值属性的确定性算法，必要时组合入场、外观切换、人物反应、镜头和静止段。先写清动作为什么发生，再使用 InlineTag 编排；自定义算法见 [程序演出](animation.md)。对同一人物属性的多个轨道检查叠加结果，不把“更动态”等同于“所有元素持续运动”。把位移、缩放、透明度等独立属性分开编排；同一属性的组合须按 motion.md 检查，避免意外覆盖。

## show 入场与 move 站位

`show` 使用 x/y 画布百分比，不接受 `to`；`move` 可用 `to` 语义位置。两者参数以 `vnve schema script` / `patch` 为准，不能把 move 的参数直接复制给 show。常用脚底基线 y=100；横版 x 为 left=25、center=50、right=75、support-left=12、support-right=88；竖版依次为 30、50、70、18、82。横竖版 off-left=-20、off-right=120。实际演员比例与镜头运动仍需试摆。

例如要从右侧入场后移到远右，用 show 的 x/y 显示，再用 move 的 `to:"support-right"` 编排；退到画外使用 move 的 `to:"off-right"`，需要停止显示时再 hide。仅要直接摆在远右时，show x=88/y=100（横版）即可，不必添加无意义移动。

## 先试片，再扩展

选覆盖主要风险的一段：两人对话、外观变化、最长台词或名字、声音停顿及一次场景交接。可以先用占位图，但明确用途。试片长度随作品调整；没有必须 15 秒或 30 秒的行业阈值。短作品可直接用全片作为试片。

检查实际文字密度、对白框、人物尺度和声音方向；存在重大风格分歧时先展示试片，再批量制作媒体。不要把用户未查看的试片写成“已认可”，也不为已授权的常规制作逐步增加确认。

同一角色的外观、背景和对白框按 [美术与素材规格](art-direction.md) 准备。优先完成一组实际画面并确认一致性，再扩展表情、时段和镜头。先建立可运行对白，再逐层加入视听元素；每次扩展都保留可播放的结果。

## 分清文字、配音与阅读时间

制作时分别考虑文字开始、揭示完成、音频开始/结束、读后停留和镜头交接。可用 `max(文字揭示结束, 配音结束) + 所需停留` 作为计划起点，再按情绪和画面信息修正；这是制作启发式；需要精确节奏时用 dialogue.timing 设置 leadIn/revealDuration/holdDuration，再由 compile 确认实际区间。

- **无声**：按语言与文本估时，再看真实播放。长句、专有名词和复杂画面通常需要额外阅读空间。根据实际观看调整 readingPace、lineGap 或可表达的 wait，不把英文词速套成统一中文字数上限。
- **有声**：使用音频真实时长，不延长或伪造 duration 来凑目标片长。保留尾字与必要阅读停留。若音频很快、字幕很多，优先拆句、重配或调整展示方式，并复查关联演出。
- **对齐**：当前行内演出按文本字符位置比例估时，不是语音强制对齐。Motion 可用节点起止锚点随台词移动，也可用本场绝对秒数。改词、拆句、换录音或调阅读节奏后，运行 compile 并核对字幕、演出和场景时长；节点锚点不提供单词级强制对齐。

文字揭示速度与揭示后的阅读等待分别设计。vnve 用 dialogue.timing 区分 leadIn、revealDuration 与 holdDuration，声音长度由真实媒体确定；具体语义见 [原子编辑](editing.md)。

## 声音跟随作品修订

逐句配音表绑定 node ID、说话人、正文快照、实际时长与来源；用户选择音色时记录到创作笔记，避免批量阶段漂移。先试听代表性句子，再批量导入。拆成多个显示节点后，相应拆分/重做音频并更新绑定；一段录音跨多个节点需要真实切点，不把整场音频随意复制到每句。

音乐可连接同一情绪段，音效标记具体事件，配音负责可懂度。先听最响音效与对白重叠处，再检查音乐进出和片尾。录音格式成功解码不代表混音质量合格。使用稳定台词 ID 关联配音，分别管理音乐、音效和人声，便于修词重配和独立混音。

voice 导入绑定台词；bgm/sfx 先导入库，再用合法行内命令编排。通过 compile.audioPlan 确认实际时窗，在网页审听音量、duck、淡出及尾音，导入成功本身不代表已经安排播放。外部工具使用沿用用户授权。

## 交付看作品，不只看编码器

对实际字体和目标观看尺寸检查：最长台词完整可读、姓名牌容纳名字、换表情不跳位、脸部不被框遮挡、镜头移动不露边。没有自动分页，溢出按语义拆句；拆句后复查音频与标签。制作长片前先处理这些可见问题，而不是给每个场景加更多特效。

顺播与跳到中间都检查，至少看开头、关键动作、长对白、转场两侧和最后一帧，听相应声音。导出后检查同样片段以及保存重开。占位素材、缺配音和未验收项逐项说明；格式检查或成功生成 MP4 不替代视听检查。结构检查发现数据问题，实际播放发现视听问题，两者分别完成。
