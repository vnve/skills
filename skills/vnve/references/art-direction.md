# 人物、场景与对白框的素材规格

为用户收集、下载或生成素材前读取。先定视觉约定，再产出文件；以下尺寸与构图由作品画幅和实际镜头决定，不是全行业统一标准，也不是强制五表情/三时段清单。

## 素材卡

向素材工具或提供素材的人传递实际需要的信息。可用简短笔记，不要求用户填写技术表单。

| 对象   | 制作前确定                                                                   | 收到文件后检查                                                                    |
| ------ | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 人物   | 身份与参考图、实际需要的状态、服饰、画风/光向、全身或半身、同套画布/对齐基线 | 透明通道、头身比例、脚底/身体基准位置、表情切换时脸和身体不跳位、边缘无白底或残影 |
| 场景   | 地点与时间、画幅、透视和光向、人物活动空间、对白安全区、计划镜头运动         | 实际尺寸、裁切后的信息完整性、人物比例、相邻时段构图连贯、运动时是否露边          |
| 对白框 | 正文区与姓名牌、实际字体/字号/行距、画幅、框图安全区与九宫格边缘             | 最长台词和名字、中英混排、缩小到目标观看尺寸、装饰与人物遮挡、九宫格拉伸          |

已有来源信息及可选许可记录按 [素材与音频](media.md) 维护，缺失不阻断制作。将角色身份、外观状态与舞台位置分开维护：同一人物复用身份与媒体组，换表情时保持脚底基准，移动时只改变舞台属性。上表是应用到 vnve 的制作约定；当前运行时使用整张立绘，不具备独立嘴型/眼睛图层控制。

## 人物：一致性比文件够大更关键

同套立绘保持画布、人物基准位置、可见身体比例与留白一致。实际文件分辨率可以不同，但如果表情图裁切、留白或头身比例不同，仅把宽高字段写成一样并不能对齐。生成下一张时复用确定的参考图和构图；下载异源素材时先比较尺度与光向，再决定是否适合混用。

**当前内核规则**：人物图片以完整图像高度归一化到画布高度的 80%，再乘 actor.scale；位置按画布百分比，锚点在图片底部中央。透明留白也属于图片范围。当前没有自定义 pivot、可见包围盒或单独脚底锚点字段。因此先在图像中统一基准，必要时预处理素材；不能承诺 import 会自动对齐身体。

例如横版 1920×1080 的初始参考高度约 864 像素，不是源文件必须高 864。不要把这个实现值变成所有画幅、所有风格的素材生产尺寸要求。横竖版分别试摆，半身图不应被当成完整全身的脚底基准。

日常/开心/愤怒/悲伤/惊讶是常用状态偏好；仅制作本轮情节需要的状态。新作可通过 script 中实际引用的 variant 预先建立外观。已有工程先 inspect，再通过 `asset.variant.create` Patch 新增外观，或用 `import register:true` 给已有组登记新媒体；按原子编辑接口补充人物状态和绑定，不覆写其他表情。

表情与外观状态的显示名（素材 variant.name、故事状态 name）沿用作品语言和用户命名；中文作品用「日常」「开心」「悲伤」或情节需要的「强忍泪水」等中文名称。内部 variantId、stateId 保持稳定，不能把英文 ID、文件名或生图提示词直接当作显示名。创建素材外观与人物状态时显式填写对应显示名；已有素材默认保留原名，用户要求调整时再通过受支持的编辑接口修改名称并保持 ID 和引用。人物立绘表情与 TTS emotion 分开：TTS 按服务接口使用英文枚举，不能据此要求立绘表情使用英文。导入后 inspect 核对素材与人物状态的显示名，并在编辑器的表情选择列表检查实际呈现。

推荐先定版默认表情，再以同一张定版图为参考派生实际需要的表情，只改变表情并固定服饰、身体姿态、画布与基线；高保真参数仅在宿主工具实际支持时使用。逐张验收后按 [图片准备](image-preparation.md) 统一变换和对齐。若选择裁剪，先合并同套非透明包围盒得到统一裁剪框，对所有图片使用同一框；不逐张紧裁导致人物尺度和脚底跳动。源图身体比例不同需要修复或重做，union bbox 本身不能纠正。

人物生成或收到文件后，按 [图片准备与检查](image-preparation.md) 完成真实透明度检查、按需抠图、同套画布对齐和浅/深底合成验收，再导入。生成工具的透明背景参数应实际启用；发现白底、棋盘格底或边缘残色时继续处理，不仅凭扩展名判断完成。

## 场景：先想镜头，再决定尺寸

保持同一地点不同时段的地平线、主要物件和人物站位空间一致。白天、黄昏、夜晚按情节需要补充。推拉/摇移前按实际 camera 轨迹检视背景边界；留边需求取决于缩放和位移，不能用一句“加大图片”保证不露边。镜头放大不会增加源图细节。

背景和人物先做一张合成试摆：脸部落点、明暗关系、视线方向、人物是否站在可信的平面上、正文是否压住关键物件。没有合成预览时，将一致性标为待检查，不仅凭提示词相似宣称统一风格。

## 对白框：先确定阅读区域，再做皮肤

正文容量由实际字体、字号、行距、正文矩形与文本共同决定，框图外观不能证明文字放得下。先放最长台词与最长名字试读，再选择框高和装饰。采用克制字幕、传统底部框或全屏文字都可以，取决于作品；需要的字段与单位见 [对白框与主题](dialogue.md)。

对白、旁白和全屏文字按阅读目的选择布局，文字样式与框图独立配置。vnve 目前没有自动分页、人物锚定气泡或任意形状文字环绕，先使用已有矩形区域和语义拆句。自定义字体通过 kind=font 导入并在主题中使用注册名称；在网页等待实际字体加载，复核正文与名字容量及字形。仅有 fontFamily 名称不能证明字体已随项目交付。

选择静态 PNG 框图时，中央文字安全区留给排版，边角装饰留给九宫格；真实检查透明度、字体与角部拉伸。网页的本场微调会创建新主题版本；完整排版和全片应用由宿主通过主题 Patch 完成。
