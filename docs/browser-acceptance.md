# 可重复执行的浏览器核心验收

维护者或宿主 Agent 运行：

```sh
pnpm build
pnpm test:browser --browser-label=codex-in-app
```

测试依赖为 Node、仓库开发依赖、当前平台发行二进制、FFmpeg/ffprobe 和支持 H.264/AAC WebCodecs、OPFS 的桌面浏览器。脚本先执行 `check:skill`；产物过期、工具缺失或环境不支持时不会降级为 mock 验收，也不会自动安装依赖。

命令输出一行 `status: ready` JSON。Agent 将其中的 `url` 打开到 Codex 内置浏览器，等待“启用声音并继续验收”按钮，再通过真实浏览器点击一次。其余步骤自动执行；用户无需逐步操作。声音按钮保留浏览器要求的真实用户手势，不使用自动播放策略开关。无人值守浏览器驱动也可以执行同样的打开、等待和点击，但必须记录实际浏览器来源，不能标成 Codex 内置浏览器。

`--browser-label` 是调用方记录，不是自动识别。报告同时保留实际 User-Agent、平台和视口。可用 `--timeout=600` 调整总超时（30–1800 秒，默认 300）；超时、被中断或未打开浏览器都返回非零退出码。

## 固定链路与断言

1. 当前独立 CLI 创建新 workspace，导入两个人物、两个背景、离线中文语音、BGM 和音效；同一算法烘焙两次，结果必须相同。
2. 浏览器加载实际发行编辑器。修改包含 InlineTag 的台词，校验正文落盘、标签保留、旧配音失效、人物身份和站位不变。
3. 点击编辑器的撤销、重做、再次撤销；保存后校验正文与原录音恢复。
4. 不点击保存按钮，等待自动保存；真正重载编辑器，检查磁盘正文、项目版本和共享素材版本。
5. 页面留下未保存草稿，再由独立 CLI 原子修改作品；检查先写恢复副本、载入外部版本、正式文件没有混入草稿、旧撤销不可用。
6. 全片预览播放时间前进、暂停后停止前进、停止回到零。
7. 通过产品的浏览器 preview bridge 捕获对白、镜头演出和双场景转场三个采样点。
8. 从正式导出面板取消一次 MP4 编码，确认未提交视频；随后同页重新导出整个作品。
9. 检查页面异常与 console.error；Chromium 无抛出异常的 ResizeObserver 延迟派发通知单独计入报告，不算脚本异常。解码实际 H.264/AAC 文件，核验 1920×1080、30fps、帧数、时长、时间戳和完整解码。
10. 预览与 MP4 对应帧按背景、人物、对白三个区域比较，归一化 RGB 平均误差各自不得超过 5%。解码后的中文语音与原语音相关性至少 0.90，偏移不超过 50ms；容差写入报告，不因失败自动放宽。

编辑通过 DOM 选择与 `beforeinput` 事件进入实际富文本控件，按钮使用实际页面处理器；不调用 React/Slate 私有对象，不直接写项目 JSON，不 mock 导出器或音频上下文。测试框架用同源回环代理承载独立 CLI 页面，以便重载后继续执行；转发时适配 Host/Origin，发行页面、会话交换和保存接口保持实际实现。首次导出的真实文件 HEAD 请求在代理中延迟 400ms，使准备阶段取消可重复触发，响应内容仍来自实际文件服务。因此本测试不替代服务安全单测，也不单独证明顶层页面与 iframe 的所有浏览器行为完全一致。

## 产物与隔离

每次新建 `.scratch/browser-acceptance/runs/<时间与随机后缀>/`，保留 `report.json`、`report.md`、源码/套件摘要、doctor 信息、最终 inspect、compile、预览与导出抽帧、视频校验数值及可播放 MP4。运行目录中的 `.vnve-acceptance-owned` 标明它是可清理测试产物。默认保留失败证据，不覆盖旧结果、不自动重试到成功。

只有所有核心检查及视频核验通过才退出 0。`pass` 不代表整个产品发布验收通过。脚本始终只创建、修改自己的新 workspace；不接收用户作品目录，不请求凭据管理接口，不打开系统播放器，不调用外部生图或 TTS。服务退出时释放端口与 CLI 进程；不在报告中保存启动会话值或 cookie。

原生中文输入法、独立宿主行为、外部 Provider、长片内存、竖屏与其他操作系统仍需另验，报告明确列出这些边界。离线语音的正文、来源与 SHA-256 见 `tests/browser/fixtures/README.md`。
